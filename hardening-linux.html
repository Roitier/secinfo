1. Fundamentos e Boas Práticas de Hardening

Hardening de Servidores é o conjunto de ações estruturadas para blindar o Sistema Operacional, reduzindo a superfície de ataque em serviços internos e externos (Web, Bancos de Dados, Arquivos).

Mínimo Privilégio

Acesso root direto bloqueado. Obriga a identificação e autenticação inicial por um usuário comum.

Superfície Reduzida

Desativação de portas inativas, daemons sem uso e encerramento de serviços expostos à rede.

Remoção de Clientes

Desinstalação de utilitários desnecessários no servidor, tais como telnet, ftpd e rshd.

2. Arquitetura Linux: Runlevels e Daemons

O runlevel determina o nível de inicialização e quais serviços/daemons serão carregados pelo sistema.

Runlevel Finalidade Ação do Sistema
Runlevel 0 Halt / Desligamento Desliga o sistema
Runlevel 1 Modo Monousuário Manutenção do sistema
Runlevel 2 - 5 Modo Multiusuário Operação regular em modo Texto ou GUI
Runlevel 6 Reboot Reinicia o sistema

Gerenciamento Manual de Daemons

bash - Controle via init.d e rcconf 
# Parar um serviço via script de inicialização
root@servidor:~# /etc/init.d/apache2 stop
[ ok ] Stopping apache2 (via systemctl): apache2.service.

# Verificar status de serviço
root@servidor:~# /etc/init.d/ssh status
[ ok ] sshd is running.

# Interface gráfica em terminal para gerenciamento do boot
root@servidor:~# rcconf

3. Vulnerabilidade e Blindagem do GRUB

A falta de senha no menu do GRUB permite que invasores físicos modifiquem os parâmetros de boot e obtenham acesso root completo injetando init=/bin/bash.

Procedimento de Proteção com Hash PBKDF2:

bash - Criptografia de Senha no GRUB 
# 1. Gerar o hash da senha
root@servidor:~# grub-mkpassword-pbkdf2
PBKDF2 hash: grub.pbkdf2.sha512.100000.A8F...

# 2. Inserir o superusuário no arquivo /etc/grub.d/00_header
cat << EOF
set superusers="root"
password_pbkdf2 root grub.pbkdf2.sha512.100000.A8F...
EOF

# 3. Atualizar as configurações do GRUB
root@servidor:~# update-grub
Succeeded. Edição do menu agora exige autenticação!

4. Restrição de Terminais Virtuais (TTY)

O arquivo /etc/securetty especifica em quais consoles o usuário root pode realizar login direto. A remoção de linhas contendo tty e vc impede o login root direto sem passar antes por um usuário comum, garantindo rastreabilidade no arquivo /var/log/auth.log.

/var/log/auth.log - Log de Auditoria 
# Tentativa bloqueada de login direto como root no terminal físico
FAILED LOGIN 1 ON tty1 FOR root, LOGIN REFUSED

# Fluxo Seguro e Auditável
ACCEPTED password for aluno from 192.168.1.50
aluno@servidor:~$ su
Password: 
pam_unix(su:session): session opened for user root by aluno

5. Systemd e Agendamentos no Crontab

Desativando Reboot por CTRL+ALT+DEL

Reduz o risco de reinicializações físicas maliciosas ou acidentais via Systemd:

bash - Desabilitando ctrl-alt-del.target 
root@servidor:~# rm /lib/systemd/system/ctrl-alt-del.target
root@servidor:~# ln -s /dev/null /lib/systemd/system/ctrl-alt-del.target
root@servidor:~# systemctl daemon-reload
Teclas CTRL+ALT+DEL desativadas com sucesso!

Sintaxe de Agendamento no `/etc/crontab`

O cron executa comandos agendados com base na estrutura de tempo do sistema:

/etc/crontab - Estrutura de Agendamento 
# m h dom mon dow user command
30 23 * * 5 root /backup.sh

# Legenda de Execução:
# Minuto: 30 | Hora: 23 (23:30)
# dom/mon (*): Qualquer dia do mês / qualquer mês
# dow (5): Sexta-feira (0-7, onde 0 e 7 representam Domingo)

6. Varredura de Portas e Finalização de Processos

Mapeamento de portas abertas com nmap e localização do PID associado via fuser para encerramento de processos não autorizados.

bash - Mapeamento e Encerramento de Porta 
# Passo 1: Varredura de portas locais
root@servidor:~# nmap 127.0.0.1
PORT     STATE SERVICE
22/tcp   open  ssh
80/tcp   open  http
9050/tcp open  tor-socks

# Passo 2: Identificar o processo que abriu a porta suspeita
root@servidor:~# fuser -v 9050/tcp
USER        PID ACCESS COMMAND
9050/tcp:            debian-tor 1470 F.... tor

# Passo 3: Encerrar o processo imediatamente
root@servidor:~# kill -9 1470
Processo 1470 encerrado. Porta 9050 fechada!

7. Filtro Host-Based com TCP Wrapper (`libwrap`)

Funciona como uma camada intermediária entre a rede e o serviço, consultando as regras de ACL antes de entregar a conexão ao daemon.

bash - Suporte e Configuração de ACLs 
# Verificar suporte à libwrap no executável
root@servidor:~# type -P sshd | xargs ldd | fgrep libwrap
libwrap.so.0 => /lib/x86_64-linux-gnu/libwrap.so.0

# 1. Bloquear tudo por padrão no arquivo /etc/hosts.deny
ALL: ALL

# 2. Configurar permissões de exceção no arquivo /etc/hosts.allow
sshd: 127.0.0.1 192.168.1.0/24
in.tftpd: 192.168.1.10

# Regra com exceção explícita:
ALL: 192.168.1. EXCEPT sshd: 192.168.1.2

8. Transferência Criptografada com SCP

Utilização do utilitário scp (Secure Copy) para transferência de arquivos criptografados sobre SSH:

bash - Exemplos de Cópia Criptografada 
# Cópia para servidor remoto na porta padrão (22/tcp)
aluno@cliente:~$ scp relatorio.txt aluno@192.168.1.100:/home/aluno/
relatorio.txt 100% 4096 2.1MB/s 00:00

# Cópia informando porta customizada (-P)
aluno@cliente:~$ scp -P 2222 backup.tar.gz aluno@192.168.1.100:/var/backups/
backup.tar.gz 100% 18MB 12.4MB/s 00:01

# Cópia de arquivo remoto para a máquina local
aluno@cliente:~$ scp aluno@192.168.1.100:/var/log/syslog ./syslog_remoto.log
